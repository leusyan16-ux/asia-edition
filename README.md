# ASIA EDITION

Платформа экскурсий и туристических активностей Юго-Восточной Азии с публичным каталогом, личным кабинетом, корзиной, заявками и административной системой. Основной язык интерфейса — русский, дополнительный — английский. География охватывает 11 стран Юго-Восточной Азии по UN M49; маршруты по территории РФ исключаются.

**Сайт:** [asia-edition.vercel.app](https://asia-edition.vercel.app)  
**Тестовое окружение и административная панель:** [asia-edition-staging-pricol1.vercel.app](https://asia-edition-staging-pricol1.vercel.app/admin/analytics)

## Стек и архитектура

**Next.js 16.4.3 · React 19.3 · TypeScript 5.9 · Tailwind CSS 4 · Node.js 24.x · pnpm 10.34.8 · PostgreSQL · Supabase**

Приложение построено на Next.js App Router. Страницы и серверные API используют общие модели предметной области: каталог, импорт, управление контентом и работа с клиентскими заявками. Серверная логика проверяет входные данные, сессии, роли и права доступа. PGlite используется для локального выполнения SQL-тестов.

Публичный каталог и административные интерфейсы работают через адаптеры данных: статический JSON, локальное хранилище, Supabase и PostgreSQL. Это позволяет отдельно развивать интерфейс, импорт и серверное хранение, сохраняя общую структуру продуктов.

## Основные подсистемы

### Каталог и управление контентом

Каталог поддерживает RU/EN, поиск, фильтры по географии и категории, сортировку, пагинацию и страницы экскурсий. Статический снимок содержит 2319 информационных карточек; две скрыты редакционным списком, публичная проекция содержит 2317.

Административная панель позволяет создавать, редактировать, дублировать и архивировать продукты, управлять описаниями, галереями, пакетами и ценами. Проверки источника, прав на контент и готовности к публикации разделены. Информационные карточки не означают гарантированную коммерческую доступность.

### Импорт и обработка данных

Импорт CSV/JSON включает предварительную валидацию, просмотр ошибок и дедупликацию по `provider + external_product_id`. Отдельно сопоставляются пакеты, страны, города и категории. Данные поставщика, редакционные изменения и коммерческие сведения разделены: повторный импорт сохраняет редакторские правки.

Для больших наборов реализованы пакетные задания, контрольные точки и продолжение после сбоя, блокировки с ограниченным сроком действия, защита от устаревшего исполнителя и повторные попытки. Импортированные продукты не публикуются автоматически. Для предоставленных материалов есть офлайн-обработка HTML/JSON/HAR; официальный поток данных поставщика не подключён.

### PostgreSQL, Supabase и безопасность

Supabase обеспечивает Auth и серверное хранение данных. SQL-миграции описывают таблицы, связи, индексы, функции и политики RLS. Каталоговый и клиентский контуры имеют отдельные зависимости и серверные разрешения. Документы и медиа используют защищённый доступ.

Авторизация административных операций выполняется на сервере. В клиентском контуре предусмотрены роли `Owner`, `admin`, `manager`, `support` и проверка MFA/AAL2 для управления. Видимость элементов интерфейса не заменяет проверку доступа к данным.

### Личный кабинет, заявки и CRM

Реализованы Supabase Auth, гостевая и серверная корзина, избранное, выбор даты и участников, контактные данные, история заявок и приватные PDF-квитанции. Оформление продолжается через менеджера; заявка не является подтверждённым бронированием. Онлайн-оплата и автоматическое подтверждение поставщиком не подключены.

CRM включает заявки, клиентов и сотрудников. Уведомления Telegram отправляются серверной очередью с повторными попытками. Dashboard показывает агрегированные показатели и графики за 7, 30 и 90 дней; активная вкладка обновляется каждые 30 секунд. Поведенческая аналитика собирается по согласию посетителя.

## Локальный запуск

Требуются Node.js 24.x и pnpm 10.34.8.

```powershell
npx --yes pnpm@10.34.8 install --frozen-lockfile
Copy-Item .env.example .env.local
npx --yes pnpm@10.34.8 dev
```

Каталог доступен по адресам `http://localhost:3000/ru/tours` и `http://localhost:3000/en/tours`. Пример окружения использует статический каталог. Для серверных интеграций параметры задаются в локальном окружении; секреты не включаются в Git.

Для локальной админпанели выполните `pnpm admin:setup`, установите `ADMIN_MODE=local`, `TOUR_DATA_SOURCE=local`, `PUBLIC_PREVIEW_ONLY=false` и перезапустите сервер на localhost. Данные этого режима хранятся в `.admin-local/`.

## Тестирование и развёртывание

```powershell
npx --yes pnpm@10.34.8 exec next typegen
npx --yes pnpm@10.34.8 typecheck
npx --yes pnpm@10.34.8 lint
npx --yes pnpm@10.34.8 test
npx --yes pnpm@10.34.8 build
npx --yes pnpm@10.34.8 start
```

Тесты охватывают предметную логику, импорт, дедупликацию, рендеринг, авторизацию и локальные SQL/RLS-сценарии. Исторические нагрузочные испытания выполнялись локально на синтетических наборах до 12500 продуктов; они отделены от результатов рабочего сайта.

Развёртывание выполняется через Vercel с отдельными окружениями Preview и Production. Конфигурация находится в `vercel.json`, параметры окружения — в `.env.example`, порядок настройки — в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
