# ASIA EDITION

Платформа экскурсий и туристических активностей Юго-Восточной Азии. Основной язык — русский, дополнительный — английский. География ограничена 11 странами UN M49 Southeast Asia; маршруты по территории РФ исключаются.

## Стек и архитектура

Next.js 16.4.3 (App Router), React 19.3, TypeScript 5.9, Tailwind CSS 4, Node.js 24.x, pnpm 10.34.8. Серверные компоненты и API выполняют проверку входных данных, сессий, ролей и прав доступа. PostgreSQL используется через pg/Supabase; PGlite — для локальных SQL-тестов.

- **Каталог:** общая модель экскурсий, RU/EN, поиск, фильтры, сортировка, пагинация и страницы продуктов. Адаптеры: статический JSON, локальное хранилище, Supabase и PostgreSQL.
- **Импорт:** CSV/JSON, предварительная проверка, идентификация по `provider + external_product_id`, сопоставление пакетов и географии. Пакетная обработка, checkpoint/resume, блокировки lease/fencing и повторные попытки. Данные источника отделены от редакционных изменений; импорт не публикует продукты автоматически.
- **Админпанель:** редактирование каталога, галереи, статусы проверки и публикации; отдельный commerce-контур для заявок, клиентов, сотрудников и аналитики. Серверные проверки ролей и MFA/AAL2 сохраняются независимо от видимости кнопок.
- **Supabase:** Auth, PostgreSQL, RLS и приватные документы/медиа. Миграции и вспомогательные SQL находятся в `supabase/`; зависимости каталогового и commerce-контуров различаются. Автоматически применять все SQL подряд нельзя.
- **Клиентские функции:** регистрация и сессии через Supabase Auth, гостевой и серверный кошик, избранное, заявки с датой и участниками, история и PDF-квитанции. Заявка не означает подтвержденное бронирование.
- **Интеграции:** серверные уведомления Telegram через outbox/retry; CRM и аналитика с согласием на поведенческие события. Роли commerce включают Owner, admin, manager и support с разными разрешениями. Онлайн-оплата и автоматическое подтверждение поставщиком не подключены.

## Данные и границы готовности

В статическом исходном снимке — 2319 информационных карточек, две скрыты редакционным списком; текущая проекция содержит 2317. Это не подтверждение актуальной цены, доступности или публикации всех записей в Supabase. Есть интерфейс будущего Klook feed/API и офлайн-разбор предоставленных HTML/JSON/HAR; действующего официального feed нет.

По ручной проверке владельца от **17.11.2026** Supabase staging имеет статус Healthy и 21 таблицу в `public`; статистическая оценка `commerce_products` — 2319 строк. Это оценка PostgreSQL, **не `COUNT(*)`** и не число опубликованных экскурсий. В рамках подготовки документации удаленное подключение не выполнялось.

Внешние Auth/email, Telegram, Storage и сценарии под реальными ролями требуют настроенного окружения и отдельной интеграционной проверки. Рабочие базы, клиентские данные, секреты и 26 рабочих редакционных карточек в исходный пакет не входят. Наборы `data/pilots/` — отдельные тестовые ресурсы.

## Локальный запуск

```powershell
npx --yes pnpm@10.34.8 install --frozen-lockfile
Copy-Item .env.example .env.local
npx --yes pnpm@10.34.8 dev
```

Каталог: `http://localhost:3000/ru/tours` и `/en/tours`. Пример окружения включает статический каталог; внешние операции выключены. Ключи в Git не добавлять.

Для локальной админпанели выполнить `pnpm admin:setup`, установить в локальном `.env.local` значения `ADMIN_MODE=local`, `TOUR_DATA_SOURCE=local`, `PUBLIC_PREVIEW_ONLY=false` и перезапустить сервер на localhost. Данные сохраняются в игнорируемой `.admin-local/`. Переключение адаптера само по себе данные не переносит.

## Проверки

```powershell
npx --yes pnpm@10.34.8 exec next typegen
npx --yes pnpm@10.34.8 typecheck
npx --yes pnpm@10.34.8 lint
npx --yes pnpm@10.34.8 test
npx --yes pnpm@10.34.8 build
npx --yes pnpm@10.34.8 start
```

Зафиксированные локальные результаты от 17.11.2026: генерация типов, TypeScript, ESLint и 140/140 тестов прошли. Первая сборка остановилась на предупреждении безопасности, повторная завершилась успешно. Версия Next.js 16.4.3 имеет зафиксированное предупреждение GHSA-mfr8-8qww-v76h; зависимости при подготовке передачи не обновлялись. Эти результаты не заменяют production-проверку. Исторические нагрузки до 12500 продуктов выполнялись локально на синтетических данных, а не на реальном каталоге в облаке.

## Структура

| Путь | Назначение |
|---|---|
| `src/app/` | Страницы RU/EN, административные маршруты и серверные API |
| `src/features/tours/` | Модель каталога, адаптеры и статический снимок |
| `src/features/admin/` | Управление инвентарем и импорт |
| `src/features/ingestion/` | Задания импорта, worker, проекции и медиа |
| `src/features/commerce/` | Auth, корзина, заявки, PDF, CRM и аналитика |
| `supabase/` | Миграции, RLS и вспомогательные SQL |
| `tests/` | Доменные, рендеринговые, импортные и локальные SQL/RLS-тесты |
| `docs/` | Технические инструкции; старые отчеты описывают состояние на свою дату |
| `public/` | Статические ресурсы и лицензии |

Для экспертной оценки подготовлен отдельный пакет `qa/VALUATION_HANDOFF` (не включается в Git). Происхождение изображений и лицензии: `docs/ASSET-SOURCES.md`, `public/fonts/OFL.txt`.
