## Що інтегровано

Змінено:

- `src/features/admin/klook-saved-json.ts`: новий офлайн-mapper спостережуваної відповіді, з перевіркою розміру, структури, ID, канонічного джерела, дублікатів і географії.
- `src/features/admin/klook-adapter.ts`: метод чинного адаптера `normalizeSavedPackages`. Існуючий транспорт feed/API не змінено; endpoint не вигадано.
- `src/features/admin/klook-offline-batch.ts`: автоматично знаходить `klook-<activity_id>-packages.json` поруч із HTML, об'єднує один запис, передає його чинному `prepareImport`. Некоректний або невідповідний sidecar утримує продукт і потрапляє в журнал помилок; не ігнорується як успішний імпорт.
- `tests/klook-saved-json.test.ts`: 4 нові регресійні тести.

Використовується попередній CLI `scripts/parse-klook-html.ts`, старі пакети <=250, ліміт імпорту 8 MiB та ідентичність `provider + external_product_id`. Нового імпортного рушія немає. JSON без відповідного HTML або перевіреного базового запису не може самостійно забезпечити назву продукту, країну, місто й категорію.

У нормалізовану модель переносяться package IDs, назви, короткі описи, package-specific inclusions і cancellation. Інша мова зберігається лише коли вихідний текст не змінився. Всі секції, виключення, eligibility, адреси, транспорт, redeem/validity instructions, SKU та показані ціни збережені в приватному `observations.jsonl`, прив'язані до конкретного пакета. Не переносяться на весь тур. Наявна модель пакета не має окремих полів для всіх цих секцій; їх збережено без втрати у супровідному файлі, а не видано за готові поля публічного шаблону.

24 наявні пропозиції перекладу HTML використано повторно як чернетки. Нові JSON-умови лишаються EN і потребують RU-перекладу/редактора. Нуль pending у попередньому HTML translation report не означає готовність перекладу нових умов JSON.

## Масштабування і наступний крок

Реальна перевірка охоплює **1 продукт**, не 900. Ізольовано оброблено 900 синтетичних saved responses чинними пакетами <=250 із повторним `skip`: 1287 мс, максимальний sampled RSS процесу Node 216 MiB. Це механічна локальна перевірка mapper/importer; не перевірка отримання 900 реальних відповідей, не performance guarantee і не production-тест. Синтетичні продукти не збережені в каталозі.

Найближчий практичний крок: отримати одним архівом **10–20 різних activity IDs** у такому форматі разом із базовим product content/географією (HTML або структурований content export), за потреби — деталями інших пакетів. Можна передати файли від представника Klook; це не вимагає нового API або ручного збереження 900 сторінок. Отримання даних автоматичним шляхом тут не реалізовано і дозволений bulk-доступ цим файлом не підтверджено.

Перевірити різні типи продуктів/валюти та представників 11 країн Південно-Східної Азії: Thailand, Vietnam, Indonesia, Malaysia, Singapore, Philippines, Cambodia, Laos, Brunei, Myanmar, Timor-Leste. Явні країни маршруту/транзиту поза регіоном і ознаки території РФ блокуються чинною географією; невідомі маршрути не погоджувати. Нові варіанти відповіді не вгадуються — схема утримує їх для перевірки.

Після узгодження зразка тим самим шляхом обробляється весь наданий архів, із дедуплікацією, звітом і чернетками. Для публікації ще потрібні точний тип тарифа/пакет/вік/дата, строки чинності, умови, придатні для ASIA EDITION, перевірені фото, RU/EN і окремі чинні погодження. **Зараз готових публічних продуктів: 0.**
