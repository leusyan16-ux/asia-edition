## Конкретна дія власника

Партнерського кабінету та API-доступу наразі немає. Запросити у закріпленого представника за чинним договором **product content feed / distributor catalog export** як CSV/JSON-файл або передачу готового файла його командою. Новий кабінет не є передумовою такого запиту. Готовий текст, перелік полів та порядок оновлення Vercel: [KLOOK_CATALOG_REQUEST.md](KLOOK_CATALOG_REQUEST.md). Потрібні:

- export CSV/JSON або документація й погоджений спосіб читання feed;
- product/package IDs, країна/місто, тип активності, назви/описи доступними мовами;
- файли або дозволені для завантаження URL фото та умови їхнього оновлення;
- валюта, тип ціни, пакет/вік, дата перевірки й термін чинності ціни, податки/обмеження;
- статус active/discontinued і час оновлення;
- перша вибірка 900+ унікальних продуктів лише Південно-Східної Азії: Thailand, Vietnam, Indonesia, Malaysia, Singapore, Philippines, Cambodia, Laos, Brunei, Timor-Leste, Myanmar. Потрібні всі країни маршруту й транзиту; територія РФ виключена.

Передати файл приватно локально в `data/` (виключено з Vercel), або надати документацію транспорту без секретів у чаті. Якщо RU/EN відсутні, потрібен редакційний переклад; не підміняти його вигаданими описами. Не трактувати пакетну або початкову ціну як підтверджену ціну дорослого.

## Використання існуючого імпортера

Офіційний формат зіставляється з `ExternalImportRecord` через існуючий `KlookAdapter`. Endpoint і схема відповіді не вигадуються. CSV/JSON, provider+external_product_id, пакети, джерела, fingerprint, повторний імпорт, checkpoint/resume вже реалізовані. Нормалізований файл проходить той самий `prepareImport`:

```powershell
node --import tsx scripts/prepare-public-feed.ts data/feed.json data/candidates.json
```

Це початкова ізольована підготовка до 5000 рядків/8 MiB, без запису в активні профілі. Для більшого feed та оновлень використовувати наявний пакетний імпортер. Синтетичні записи відхиляються. Усі нові записи — чернетки. Вхідний формат не є заявленим форматом API Klook.

Редактор працює локально з існуючою адмінпанеллю. Перевірити RU/EN, категорії, місто, джерело, право використання, ціни. Новий Сінгапур підтримується в локальній TS-моделі/навігації; SQL-схема колишніх 13 країн не змінена. Для него додана власна графіка, не фотографія. Невідомі категории потрібно погодити й додати до taxonomy, не маскувати під інші.

## Окреме погодження публікації

Експортер читає **окремий приватний JSON** `{tours: AdminTour[], taxonomy: TourTaxonomy}`; не читає активні профілі чи `.env.local`. Чернетка не стає публічною від імпорту. Для комерційної картки потрібні status=published, visible, !archived, !isDemo, verifiedAt; external source=active, editorial=approved, rights=licensed з evidence, readiness=ready. Наявні строгі правила адміністративної публікації залишаються чинними.

Фото перед експортом мають бути дозволені й завантажені в `public/images/` із власними унікальними назвами. Автоматичного скачування немає: raw URL feed може бути підписаним або тимчасовим. Приватні `/images/admin/`, remote URL та path traversal блокуються. Наявність файлів перевіряє CLI. Рекомендовано оптимізовані JPEG/WebP/AVIF; не використовувати гігантські оригінали.

```powershell
# Створює НЕ погоджений worksheet; false замінює редактор після перевірки.
node --import tsx scripts/export-static-catalog.ts data/approved-candidates.json - data/reviews.json
# Після окремого погодження publicationApproved, imagesApproved та geographyApproved=true:
node --import tsx scripts/export-static-catalog.ts data/approved-candidates.json data/reviews.json data/public-snapshot.json
```

Кожне погодження прив'язане SHA-256 до всього документа; зміни або повторний імпорт потребують нового погодження. Вихідний файл створюється тільки якщо **всі** записи пройшли перевірку; існуючі файли не перезаписуються. Дублікати provider+ID, slug та UUID блокуються. Ціни мають verifiedAt, validFrom/validUntil; після завершення строку ціна приховується на запиті сервера. Інвентар місць у snapshot завжди порожній.

Перевірений snapshot вручну замінює `src/features/tours/published-catalog.json`. Він містить тільки публічні поля, taxonomy й строки чинності цін; provider, source URL, права/evidence не потрапляють на сторінки. Приватні файли не переміщувати у src/public.

Лише коли кількість погоджена, змінити **обидва** `TOUR_DATA_SOURCE` у `vercel.json` на `static`; зберегти PUBLIC_PREVIEW_ONLY=true, ADMIN_MODE=disabled та інші блокування. `.env.local` не змінювати. Потім typecheck, lint, tests, build, перевірка з `TOUR_DATA_SOURCE=static`, повторний деплой у наявний Vercel-проєкт. Демо залишається в окремому demo-адаптері; не змішується зі static. Без нового деплою відкликання в приватних вихідних файлах не змінить публічний snapshot — відкликати продукт у snapshot та перевикласти.

## Перевірки й обмеження

Регресійні тести використовують 900 **ізольованих синтетичних fixtures у пам'яті**, не реальний асортимент. Перевіряються права, окремий дозвіл, чернетки, дедуплікація, відсутність приватних метаданих, expiry цін, RU/EN-пошук/фільтри, пагінація, деталі. Реальні фотографії, дані feed й ціни перевірити неможливо до їх отримання. Ніяких Supabase-підключень, бронювань, оплат або публікації чернеток цей механізм не вмикає.

Географічний контроль: імпорт перевіряє основну країну, явні країни `routeCountries`, імпортовані локації та текстові ознаки заборонених маршрутів. Для статичного експорту обов’язкове окреме `geographyApproved=true`, прив’язане до SHA-256 документа: редактор перевіряє весь маршрут і транзит, включно з відсутністю території РФ. Автоматична перевірка тексту не доводить безпечність неповного маршруту. Неповні дані не погоджувати.
