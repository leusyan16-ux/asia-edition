# Пакетне опрацювання реального HTML Klook

Стан на 25.10.2026. Локальний офлайн-процес, без запитів до Klook, обходу 403, Supabase, публікації, оплати чи бронювання. Публічний сайт не змінено. Це розширення чинного CLI/моделі, а не новий імпортер або сервер.

## Що автоматизовано

- Рекурсивне виявлення до 5000 HTML у підпапках input; `_files` та symlink не обходяться. До 16 MiB на HTML. Вхідний HTML читається послідовно, весь набір HTML не завантажується в пам'ять.
- ID/canonical URL, назви, описи, пакети та package IDs із відомого DOM, неперевірені ціни й валюти, JSON-LD/видимі діапазони тривалості, кандидати зображень.
- Країна — структурована адреса, потім явний country breadcrumb. Місто — addressLocality, потім city breadcrumb; відома локальна назва зіставляється, невідома зберігається з вихідного тексту зі стабільним slug. Конфлікти країн/локалізованої географії утримуються. Папка `thailand/` сама по собі не є доказом країни.
- Категорія — явне значення зі словником зіставлення; якщо його немає, обмежене припущення з назви (museum/cruise/gardens/transfer тощо). Таке припущення позначене `title-inference-needs-review`, не є підтвердженим фактом. Невідомі категорії не вгадуються безмежно.
- Перевірка локальних image references, реального розташування всередині input, розміру, сигнатури й metadata JPEG/PNG/WebP/AVIF. HTML/SVG під виглядом JPG не передається декодеру. Фото не завантажуються з Інтернету й не потрапляють у public. Технічний декод не означає візуальний огляд або дозвіл на використання.
- Дублі provider/product ID в одному наборі не стають другим записом. Обидва джерела не перезаписуються; source variant вимагає огляду. Це не злиття мовних версій або джерел із різними редакційними правками.
- Наявний prepareImport перевіряє дані; вихідні JSON-файли мають максимум 250 продуктів та ліміт 8 MiB. Повторний план імпорту перевіряється на skip, без запису в активний профіль.

## Файли та запуск

```powershell
node --import tsx scripts/parse-klook-html.ts data/manual-klook-html/input-02 data/manual-klook-html/batch-02
```

Ресурси кожної сторінки мають залишатися поруч із відповідним HTML. Можна розкласти сторінки по країнах. Шлях/назва в manifest для вкладеного файла, наприклад `thailand/123-en.html`, використовує `/`.

Результати створюються лише в **новій** вихідній папці:

- `products.json`, далі `products-002.json` тощо — файли чинного імпортера; точний список у `report.json.batches`.
- `observations.jsonl` — окремий JSON-рядок на прочитане джерело, з текстами, ID, цінами-спостереженнями, джерелом і SHA-256.
- `quality.jsonl` — звіт на кожен файл, включно з помилками/дублікатами: повнота 13 груп полів, походження географії/категорії, фото, ціни, пакети, переклади, status та publication gate.
- `translation-tasks.jsonl` — вихідний текст/мова, цільова мова, стабільний key, hash тексту, пропозиції й помилки.
- `report.json` — real/synthetic, лічильники, країни, пакети імпорту, repeat skip, час/RSS, готовність до публікації.

JSONL читається построково; це приватні робочі файли, не публічний feed. Якщо немає повного RU/EN або mapping, дані залишаються у звітах, а не стають порожньою пропозицією. Обробка помилки одного HTML не зупиняє інші. Після аварійної зупинки не вважати неповну папку завершеною: вибрати новий output і повторити офлайн-обробку; завантажені JSON використовують уже наявну дедуплікацію імпортера. Нового checkpoint engine не створено.

Старий формат одиничного `observations.json` залишився у попередніх результатах; нові запуски використовують `observations.jsonl`. Старі файли й каталоги не змінювалися.

## RU/EN переклад: що працює, а чого ще немає

Після вибору власником локального перекладача встановлено **CTranslate2 4.8.3 + SentencePiece 0.2.1** та дві моделі Argos 1.9 EN→RU/RU→EN. Дані й Python-бібліотеки лежать лише в `data/manual-klook-html/local-translation/`, не в системному Python і не в Node dependencies. Моделі завантажено з [офіційного каталогу Argos](https://www.argosopentech.com/); CPU inference використовує [CTranslate2](https://opennmt.net/CTranslate2/python/ctranslate2.Translator.html). SHA-256/версії/джерела архівів записані в `model-provenance.json`. Ваги й runtime не потрапляють у Git/Vercel.

**Автоматичний локальний переклад фактично перевірений:** реальний Gardens by the Bay без ручного manifest — 26 задач, 22 пропозиції утворено для draft, 4 утримано перевірками помилок. Оброблено за 6744 мс, RSS батьківського Node.js — 110 MiB; пам'ять Python/моделей цим значенням не виміряна. Окремий smoke EN→RU і RU→EN пройшов за 1245 мс (`local-translation-smoke.json`), це перевірка напрямків, не оцінка якості всього каталогу. Текст не надсилався у сторонні сервіси. Python worker не містить завантажувача/HTTP-клієнта та блокує Python socket connect/sendto; завантаження ваг — окрема одноразова операція без продуктового контенту.

Виявлені реальні похибки MT: `Tram` → «альбом», literal high tea, redemption voucher → «выкуп». Додано точкові захисні перевірки, чотири відповідні поля **не переносяться у draft**. Це не універсальна семантична перевірка: решта 22 також потребують редактора. Ранні результати `batch-real-local-01` збережено для трасування, але **остаточний результат із фільтрацією — `batch-real-local-auto-01`**, готовність до публікації 0.

Для реального ID 127 Codex підготував 24 RU пропозиції (7 назв + 7 описів пакетів, 5 назв + 5 описів highlight), окремо від уже наявної RU назви й короткого опису продукту. Це AI-чернетки на огляд, не результат встановленого локального MT. `data/manual-klook-html/translation-provenance-127.json` фіксує походження. Усі сім пакетів мають RU/EN тексти в новому draft JSON. Перекладені highlights збережені серед пропозицій для огляду; не підміняють редакційний контент автоматично.

Цей попередній набір чернеток зберігається окремо в `batch-real-04`; його не слід плутати з новим автоматичним результатом `batch-real-local-auto-01`, де залишилися 3 незаповнені RU назви пакетів і ще один утриманий RU опис через знайдені помилки MT.

Ключ і SHA-256 прив'язують пропозицію до поля, мови й вихідного тексту. Застарілі пропозиції не застосовуються, дублікати/неправильний формат/зміни числових фактів відхиляються. Це механічна перевірка, не гарантія правильності перекладу. Наявний редакційний текст не затирається. Прийняті пропозиції можна додати лише до draft; `reviewStatus=needs_review`, source editorial=pending, права unknown, publication blocked.

Необов'язковий четвертий аргумент — довірений локальний config, третій `-` означає відсутність manifest:

```json
{
  "dataset": "real",
  "proposalsFile": "data/manual-klook-html/translation-proposals-127.json"
}
```

```powershell
node --import tsx scripts/parse-klook-html.ts data/manual-klook-html/input-01 data/manual-klook-html/NEW-RESULT data/manual-klook-html/editorial-mapping-01.json data/manual-klook-html/batch-real-config-01.json
```

Для локальної моделі config підтримує `localTranslation: { executable: ABSOLUTE_LOCAL_PATH, args: [...] }`. Команда читає JSON-масив задач зі stdin та повертає JSON-масив `{key,sourceHash,targetText}` у stdout. По 20 задач із обмеженням розміру; timeout 60 с, stderr/stdout обмежені. shell=false, API endpoints і секрети з env не використовуються. Передаються offline flags для бібліотек HuggingFace. Проте запуск довільного процесу не є мережевою пісочницею — використовувати лише перевірену **справді локальну** програму, не виконувані файли зі збережених ресурсів Klook. Поточний Python-worker додатково блокує Python socket-з'єднання.

**Вибраний локальний runtime вже встановлено й перевірено на цьому комп'ютері.** Наведений опис протоколу також дозволяє майбутню заміну рушія. Робочий config — `data/manual-klook-html/local-translator-config.json`, він містить лише локальні шляхи, без ключів. Наступна партія з локальним автоперекладом:

```powershell
node --import tsx scripts/parse-klook-html.ts data/manual-klook-html/input-02 data/manual-klook-html/batch-02 - data/manual-klook-html/local-translator-config.json
```

Для відновлення на іншому комп'ютері: Python 3.12, `pip install --target data/manual-klook-html/local-translation/packages --only-binary=:all: -r scripts/local-translation-requirements.txt`, потім `python scripts/setup-local-translator.py` (тільки первинне встановлення), і оновити абсолютний шлях Python/script у локальному config. Модельний installer отримує лише публічні ваги послідовними стандартними HTTP Range; перевіряє Content-Range, Zip CRC при читанні, мови й безпеку шляхів архіву. Існуючі встановлені моделі не перезаписує. Немає потреби повторювати інсталяцію перед кожною партією. Підтримка нового комп'ютера ще не перевірена.

## Реальні та синтетичні результати — окремо

**Підсумкова чернетка для редактора:** `data/manual-klook-html/batch-real-final-draft-01/products.json`. Один і той самий ID 127, сім пакетів із RU/EN назвами/описами. 22 перекладні пропозиції отримані з локальної моделі, ще 4 виправлені AI-чернетки прив'язані до source hash й підставлені окремо (`translation-corrections-127.json`). Сировий тест MT з 4 відхиленнями не приховується; див. `batch-real-local-auto-01`. Усі 26 пропозицій досі needs_review, 0 продуктів готові до публікації. Залишається повна редакційна перевірка, а не тільки ці 4 виправлення.

Повнота 13/13 означає наявність полів, **не перевіреність чи готовність до продажу**.

Synthetic dataset має provider=test_fixture, test_data=true. Синтетичні позначення в real dataset блокуються. Усі дані тут виключені з Git/Vercel. Повний набір локальних тестів — 76/76 PASS; фінальні профільні перевірки охоплюють пакетні 900, сім країн, дедуплікацію, challenge/пошкоджені зображення, країни-конфлікти, числові факти перекладів, timeout/неправильний response перекладача й publication gates. ## Трудомісткість 900 і найкоротший дозволений шлях

Фактично виміряно локальну обробку, **час ручного збереження/редактури не вимірювався**. Немає підстав обіцяти строк повного каталогу за одним файлом. Сценарій для планування, не результат заміру:

- 2–4 хв на пошук/збереження/перевірку вихідних файлів × 900 = 30–60 людино-годин.
- 5–10 хв на зміст, переклади, фото, mapping цін і рішення редактора × 900 = 75–150 людино-годин.
- Разом 105–210 людино-годин; збої, складні пакети та підтримка актуальності можуть додати час. Ці припущення треба замінити вимірами на наступній партії.

Локальне читання HTML автоматизується, а ручне збереження не можна автоматично замінити заблокованими HTTP-запитами. **Доступний прямо зараз спосіб** — зберігати дозволені сторінки у звичайному браузері, партіями й одразу з ресурсами. Для сотень сторінок найсильніше прискорення дасть структуроване bulk-вивантаження або дозволений доступ від власника джерела: можна запитати саме файл у менеджера Klook **без створення партнерського кабінету/API-доступу**. Доступність такого файла не стверджується. Якщо він не наданий — залишається ручний capture; жодного anti-bot/cookie/proxy обходу або неофіційного приватного API.

## Конкретна наступна партія (оновлено)

Поточний спосіб — один приватний sanitized HAR для 10–20 звичайно відкритих activity-сторінок, без копіювання кожної JSON-відповіді. Інструкція та мінімальні поля: [KLOOK_NEXT_BATCH.md](KLOOK_NEXT_BATCH.md). Не потрібно вручну зберігати 14 HTML. Географія — лише 11 країн Південно-Східної Азії; попередній перелік із Japan/South Korea більше не чинний. Raw HAR зберігати приватно під data/, без account/checkout, входу чи sensitive export.

Змінені файли: `src/features/admin/klook-offline-html.ts`, `klook-offline-batch.ts`, `offline-translations.ts`; `scripts/parse-klook-html.ts`, `local-translate.py`, `setup-local-translator.py`, `local-translation-requirements.txt`; `tests/klook-offline-html.test.ts`, `klook-offline-batch.test.ts`; `eslint.config.mjs` (виключення приватних HTML/runtime із lint), інструкції. Нових залежностей Next.js/міграцій/серверів немає; Python CPU-залежності встановлені тільки в приватну папку. `.env.local`, Vercel-конфігурація, public snapshot і 26 карток не змінювалися.
