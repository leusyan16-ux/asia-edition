## Як збережені дані

Робоче сховище: **`.admin-local/tours.json`**, стандартний локальний JSON-адаптер. Не новий паралельний каталог і не Supabase. Наявні незалежні профілі не об'єднувалися й не змінювалися. Перед наступними проходами імпорту створено повні резервні файли `.admin-local/before-getyourguide-*.backup.json`; перший запис був у порожній робочий tours.json.

Використані `prepareImport`, `commitExternalImport`, preview digest, журнал та пакети <=250 записів. Ідентичність — `provider=getyourguide` + незмінний `source_product_id`; slug — `getyourguide-ID`. Повторний імпорт не знищує редакційні правки. Нормалізована ревізія враховується в batch ID, тому повторний файл з адаптованим mapping не конфліктує зі старою імпортною транзакцією.

У моделі додано опційне приватне `externalProduct.source_metadata`. Воно бере участь у fingerprint, але не виходить у public Tour payload. Там збережені всі оригінальні поля CSV, українські назви, source_files, посилання на фото, показана ціна/валюта, рейтинг, сирі особливості/тривалість і походження mapping/перекладу. Воно доступне в адміністраторському редакторі в розділі даних джерела. Нове поле не надає дозволів і не замінює editorial/rights/publication status.

Усі 159 наданих показаних цін збережено як спостереження, з вихідною USD і без конвертації. Вони не видаються за перевірену ціну дорослого/дитини на конкретну дату. Рейтинги теж збережені приватно без додавання вигаданих reviews/count. Root prices/images/availability порожні.

Фіксовані явні тривалості перетворені на хвилини; діапазони, дні/ночі та неоднозначні фрази не перетворено на середнє. Повний початковий текст лишився в source_metadata. Особливості з CSV не видані за розклад, включені послуги або детальний маршрут.

## RU/EN та вигляд

Початкові назви тільки українські. Наявні локальні моделі підтримують EN/RU, а не UK. Тому EN-чернетки сформовано з наданих англомовних URL-slugs; вони не заявлені як офіційна назва постачальника. Наявним офлайн-перекладачем створено 293 RU-пропозиції, прив'язані до sourceHash. Усі потребують редактора; оригінальні UK-назви збережено. Немає стороннього translation API або нового завантаження моделей. Короткі редакційні описи не додають непідтверджених послуг/операторів/розкладу.

Картки без фото тепер мають нейтральне типографічне оформлення «Без фотографии / No photograph», без hotlink або сторонньої фотографії. За відсутності перевіреної ціни працює чинне нейтральне повідомлення. Порожні локалізовані розділи detail-template приховуються. URL фото не перевірялися зовнішніми HTTP-запитами й не вважаються підтвердженими зображеннями.

Підсумкові файли: **`data/getyourguide-294/import-final/`**:

## Перегляд у браузері

Поточні `.env.local` і Vercel залишають ADMIN_MODE=disabled, TOUR_DATA_SOURCE=demo. Для локального перегляду використати окрему PowerShell-сесію, **не змінюючи `.env.local` чи Vercel**:

```powershell
$env:ADMIN_MODE="local"
$env:TOUR_DATA_SOURCE="local"
$env:ADMIN_LOCAL_DIRECTORY=".admin-local"
$env:PUBLIC_PREVIEW_ONLY="false"
# Якщо в цьому робочому профілі ще немає identity.json:
npm run admin:setup
npm run dev
```

`admin:setup` інтерактивно створює локальний вхід; це не Supabase Auth. Не надсилати пароль у чат. Відкрити `http://localhost:3000/admin`, увійти, знайти GetYourGuide-картку та відкрити її protected preview у RU/EN. Конкретні UUID/посилання — в `admin-links.json`. За потреби вибрати Draft, Thailand/Laos і скористатися пошуком.

Публічний `/ru/tours` у локальному режимі теж **не покаже чернетки**. Для їх перегляду потрібен administrator preview, а не встановлення status=published. Інформаційні посилання й підтверджені факти не означають автоматичне право комерційної публікації.

## Що блокує публікацію і що робити далі

Публікація заборонена фактичними статусами наданого файла. Потрібні підтвердження прав на контент/конкретні фото та editor review перекладів/класифікації/повного маршруту. Чинні комерційні publication guards також вимагають перевірки оператора/дати, фотографії, тривалості та для static snapshot — підтвердженого тарифу зі строком чинності й окремих publication/image/geography погоджень. Оператор у файлі не наданий, ціни/фото не можна домислити. Ці правила не послаблювалися для отримання числа 294 на сайті.

Найкоротший шлях: перевірити невелику підмножину в адмінпанелі, додати підтвердження/дані постачальника та дозволені фото, виконати чинний статичний export погоджених записів і перевірки, після чого повторно розгорнути **той самий** Vercel-проєкт із static-адаптером. Supabase для цього не обов'язковий. Для інформаційної публікації без комерційних полів потрібна окремо погоджена зміна політики; цей імпорт її не підміняє.

**Зміни на Vercel наразі не доступні: деплой не виконувався.** Raw data та робочі профілі виключені з Git/Vercel. Новий deployment без статичного погодженого snapshot сам по собі не додасть чернетки до публічного каталогу.
