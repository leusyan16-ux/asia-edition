# Заявка на бронювання через Telegram — 26.10.2026

Додано безпечний ручний канал запиту до наданого власником публічного бота `https://t.me/VietnamTravelVN_bot`. Це не підтверджене бронювання й не автоматична доставка в операторський чат.

Production deployment `dpl_DZwe4RborFHErrn62h3zkWFN7DXy` успішний, READY; https://asia-edition.vercel.app оновлено.

## Користувацький сценарій

На детальній сторінці: «Запросить бронирование» → ім’я, бажана дата, кількість дорослих/дітей, коментар і згода → «Подготовить заявку» → копіювати текст → відкрити Telegram-бот → за потреби Start → вставити й надіслати повідомлення.

Форма не надсилає нічого сама, не зберігає персональних даних на сайті, не резервує місця, не приймає оплату й не показує фіктивного підтвердження. Якщо clipboard недоступний, текст залишається виділюваним у textarea для ручного копіювання. Проєкт не підтверджує фактичне отримання повідомлення ботом чи менеджером.

Deep link містить лише slug продукту (до 64 дозволених Telegram символів), без імені, дати, коментаря чи chat ID. Валідуються домен/HTTPS/username бота, адреса email для альтернативного каналу, дата, згода й обмеження до 30 гостей. Немає нових відкритих серверних API. Старі admin/inquiry API залишаються закритими.

Офіційний формат Telegram: https://core.telegram.org/bots/features#deep-linking. Поведінка чинного бота щодо `/start` і довільного тексту потребує перевірки власником; ми не змінювали його webhook, код або налаштування та не надсилали тестових повідомлень.

## Конфігурація

`BOOKING_TELEGRAM_URL=https://t.me/VietnamTravelVN_bot` додано до runtime і build env у vercel.json. Це публічне посилання, не токен. За відсутності коректного каналу форма прихована. Альтернатива — серверна `BOOKING_CONTACT_EMAIL`, що відкриває підготовлений лист у поштовому клієнті; лист також надсилається лише користувачем.

Наданий власником операторський chat ID не вбудовано у браузер, HTML, bot start payload або публічний manifest. Автоматична доставка у цей чат не реалізована без підключення серверного Bot API. Для наступного кроку потрібні перевірена логіка приймання/пересилання повідомлень ботом або серверна інтеграція з `TELEGRAM_BOT_TOKEN` та `TELEGRAM_CHAT_ID`. Секретний токен зберігати лише у Vercel server Environment Variables, не в чаті, `.env.local`, NEXT_PUBLIC або репозиторії. Потрібні також захист від спаму та реальний тест доставки перед обіцянкою приймання заявок.
