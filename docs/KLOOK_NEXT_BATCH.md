# Наступні 10–20 продуктів: один HAR із браузера

Стан 25.10.2026. Це невеликий офлайн-перехідник до чинного імпортера, а не новий етап каталожної архітектури. Дані не публікуються.

## Мінімальні дані на один activity ID

| Дані | Навіщо |
| --- | --- |
| Activity ID і канонічний HTTPS URL продукту | Ідентичність `klook + activity_id`; package/SKU IDs не рахуються як продукти. |
| Назва продукту, опис, мова оригіналу | Джерело для RU/EN. Якщо є лише EN, працює чинний локальний перекладач; результат — чернетка на перевірку. Сам JSON пакетів цих даних не замінює. |
| Підтверджені країна, місто/курорт і категорія | Географія/фільтри. Якщо HTML metadata їх не містить, продукт утримується до фактичного mapping; країна не вгадується з ціни чи назви. |
| JSON `success/result/activity_id/spu_group_info` | Для цієї перевірки потрібні реальні package IDs, назви/описи та спостереження цін. Докладні умови `first_spu_detail` належать лише його `spu_basic.spu_id`. |
| Джерело й час отримання | HAR лишається приватним первинним джерелом; вихідний звіт зберігає його SHA-256. Час локального імпорту не є часом перевірки ціни. |

Для базової чернетки фотографії та підтверджена ціна не обов'язкові. Для публікації чинні вимоги не послаблюються: точний пакет/тип тарифу/вік/дата/валюта/строк ціни, перевірені фото й права, RU/EN та окремі погодження. HAR не робить `has_stocks` календарем, а `publish_status` — дозволом ASIA EDITION на публікацію.

Регіон: Thailand, Vietnam, Indonesia, Malaysia, Singapore, Philippines, Cambodia, Laos, Brunei, Myanmar, Timor-Leste. Усі країни маршруту й транзиту мають бути в регіоні; територія РФ виключена. Невідомий повний маршрут не погоджувати автоматично.

## Що зробити власнику в Chrome

1. Відкрити окреме вікно інкогніто без входу в Klook. Не переходити до account/checkout і не вводити особисті дані.
2. Відкрити DevTools (`F12`) → **Network**, увімкнути **Preserve log**. Переконатися, що запис увімкнено, очистити журнал перед початком. DevTools має бути відкритим до завантаження першої сторінки.
3. **У цій самій вкладці** по черзі відкрити 10–20 різних сторінок activity. Дочекатися назви, опису й завантаження блоку пакетів. Якщо пакети відкриваються звичайною кнопкою — відкрити її один раз. Не копіювати JSON, не виконувати `fetch`/cURL, не підбирати endpoints/IDs і не змінювати User-Agent. Не переходити до покупки. Кожний URL достатньо відвідати один раз; не перемикати багато варіантів пакета в першому записі, щоб уникнути конфліктних snapshots.
4. Якщо бачите блокування, CAPTCHA або 403 — припинити спроби для цієї сторінки, не обходити обмеження. Можна пропустити її та зазначити, що вона недоступна.
5. Для компактного файла можна встановити фільтр **`domain:www.klook.com`**. Експортувати **HAR (sanitized)** / **Save all listed as HAR (sanitized)**. **Не вмикати “with sensitive data”.** Не обмежувати список лише Fetch/XHR: потрібні також відповіді Document/HTML. Розмір — до 64 MiB; якщо більший, робити менші записи по 5–10 сторінок.
6. Зберегти один файл: **`data/manual-klook-html/har-input-01/klook-next-10-20.har`**. Не надсилати raw HAR у публічний репозиторій або на сторонній HAR-viewer: навіть sanitized HAR може містити приватні дані в URL/тілах відповідей. Папка data виключена з Git/Vercel.
7. Повідомити шлях до файла. Решту локального розпакування, mapping, перекладу й перевірки виконає агент. Не потрібно окремо зберігати кожен HTML або копіювати JSON.

Важливо: **Preserve log діє в одній вкладці**, не об'єднує всі вкладки браузера. HAR може не містити потрібних response bodies або rendered DOM. Це перевіряє новий звіт; не можна вважати збережені лише заголовки повним каталогом. Якщо bodies відсутні, не потрібно вмикати sensitive export: спочатку перевірити запис на 2–3 сторінках. Якщо HTML не містить потрібних metadata, існуючий імпортер утримає продукт; потрібен фактичний content export або точкове доповнення mapping.

[Офіційна документація Chrome](https://developer.chrome.com/docs/devtools/network/reference/#save-all-network-requests-to-a-har-file) підтверджує Preserve log та sanitized HAR; sanitized прибирає Cookie/Set-Cookie/Authorization headers, але не гарантує повної анонімізації response content.

Для старту підготовлено **11 уже наявних URL-кандидатів, крім activity 127**, у `data/manual-klook-html/next-browser-capture-candidates.md`. Вони всі із Сінгапуру й не перевірені повторно на актуальність/доступність. Це швидкий transport pilot, не покриття 11 країн. Частину можна замінити сторінками інших дозволених країн, які нормально відкриваються, та різних типів продуктів.

## Обробка без нового імпортера

```powershell
node --import tsx scripts/unpack-klook-har.ts data/manual-klook-html/har-input-01/klook-next-10-20.har data/manual-klook-html/har-extracted-01
node --import tsx scripts/parse-klook-html.ts data/manual-klook-html/har-extracted-01 data/manual-klook-html/har-drafts-01 - data/manual-klook-html/local-translator-config.json
```

Завжди використовувати нові output-папки. Якщо потрібен уточнений country/city/category mapping, третій аргумент другого CLI замінюється існуючим manifest-файлом; не вигадувати відсутні факти.

`unpack-klook-har.ts` читає лише локальний файл до 64 MiB/20 000 entries. Приймає успішні HTTPS-відповіді з www.klook.com/klook.com, розпізнає HTML activity та вже спостережувану структуру JSON без припущень про endpoint. Не повторює жодного запиту. Записує інертні metadata HTML й allowlisted package fields. Заголовки, cookies, POST bodies, account scripts і форми не експортуються. Це не універсальний sanitizer довільного контенту: первинний HAR залишається приватним.

Одна папка на activity ID, один sidecar `klook-ID-packages.json`. Точні дублікати ігноруються; різні відповіді для одного ID утримуються як конфлікт, а не довільно перезаписуються останньою ціною. Пропущені bodies і невідомі формати показуються в `har-report.json`. Цей звіт рахує знайдені пари, **не готові до публікації продукти**. Далі працюють чинні географія, переклад, `prepareImport`, якість, <=250 записів / 8 MiB та дедуплікація. Усі результати — приватні чернетки; активний локальний каталог не змінюється без окремого імпорту.

## Отримання даних і оцінка 900+

[Klook офіційно пропонує data feeds](https://affiliate.klook.com/home), але відкритого CSV/JSON без доступів не знайдено. Потрібно уточнити можливість передачі bulk-файла представником за чинним договором — це не вимагає обов'язково створювати партнерський кабінет. Готовий запит: `docs/KLOOK_CATALOG_REQUEST.md`. Наявність договору прийнята; повторного юридичного аудиту не проводилося. Supplier/OCTO API не видається за reseller catalog export.

Публічні сторінки й indexed snippets дають лише кандидатів і неповні відомості; не забезпечують підтверджені пакетні тарифи, фото й актуальність 900 продуктів. Заблоковані HTTP-запити не повторювалися. HAR — пасивна передача результату звичайного браузерного перегляду, а не доказ дозволу на автоматичний scraping.

Для 900+ технічна обробка є пакетною; **отримання джерел лишається основним обмеженням**. Припущення для планування: якщо звичайне відкриття/очікування займає 30–60 секунд на продукт, 900 потребуватимуть 7,5–15 годин лише перегляду, без редактури й перевірки умов. Це арифметична оцінка, не вимірювання реального capture. Для регулярних оновлень надійніший bulk content/package export від джерела; HAR доцільний для наступних 10–20 і перевірки варіативності, а не обіцянки повного актуального комерційного каталогу.

## Фактично перевірено

- Реальні нові 10–20 продуктів і справжній HAR ще не надані. Не проводилося реального browser HAR-тесту. Існуючий реальний HTML+JSON activity 127 повторно пройшов старий CLI: 1 кандидат, 7 пакетів, повторний skip, 0 готових до публікації. Результат `data/manual-klook-html/batch-readiness-20-actual-127/`.
- 20 **синтетичних** HAR-пар → чинний імпортер → 20 уникальних draft-кандидатів; replay skip=20. Географічні негативні випадки Japan/Russia відхилені. Перевірені base64, duplicate/conflict, 403/foreign host, missing bodies, відсутність request secrets в extracted output.
- TypeScript, ESLint — PASS; повний набір **86/86**. Немає змін публічного сайту, Supabase, бронювання/оплати або 26 карток. SHA-256 26 карток: `A69096516AEEC450D568CC65E4C4571395E49E8E56C95DED2149F2193AE7D537`.
- Створено `src/features/admin/klook-har.ts`, `scripts/unpack-klook-har.ts`, `tests/klook-har.test.ts` та цей документ. Імпортний рушій і модель не переписувалися.
