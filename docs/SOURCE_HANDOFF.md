## Перевірка безпеки

`node scripts/check-source-handoff.mjs` перевіряє набір робочих кандидатів, `node scripts/check-source-handoff.mjs --staged` — саме байти Git index. Значення секретів не друкуються. Перевіряються типові ключі/JWT/приватні ключі/рядки доступу, заборонені шляхи та збіги зі значеннями секретних параметрів локального середовища. Звіт і SHA-256 маніфест створюються в ігнорованій `qa/`.

Дві перевірені виняткові відповідності — негативний TLS-тест із URL домену `db.example.invalid` та перевірка відмови для Telegram URL із фіктивними user/password. Це не робочі доступи. Відомі публічні контакти бренду та ідентифікатори історичного staging не є ключами доступу. Автоматичний сканер не є математичною гарантією відсутності будь-яких невідомих форматів секретів.

## Перевірки відтворюваності

17.11.2026 перевірено ізольовану копію staged-файлів без `.env.local`, робочих БД і хмарних доступів, із використанням уже встановлених залежностей. `next typegen`, TypeScript, ESLint і **140/140 тестів** пройшли. Це не повторне встановлення залежностей із registry та не перевірка живих інтеграцій.

Чиста Next.js/webpack-збірка скомпілювала код, перевірила типи та згенерувала 55 статичних маршрутів, але завершилася з кодом 1 через `SecurityFatalError`: встановлений Next.js 16.4.3 потрапляє під [GHSA-mfr8-8qww-v76h](https://github.com/advisories/GHSA-mfr8-8qww-v76h), moderate, виправлено у 16.4.5. Конкретну експлуатованість застосунку не встановлено; `unstable_cache` / `use cache` у `src/` не знайдено. Захисну перевірку не вимикали, залежності не змінювали. Повторний запуск тієї ж webpack-збірки завершився успішно (код 0), без зміни залежностей чи вимкнення захисту. Це не усуває advisory. Історичні staging/production build-звіти не замінюють цей новий результат.

## Початковий коміт і приватний GitHub

Репозиторій спочатку не містив комітів. Увесь перевірений вміст підготовлюється локально; завантаження не дозволене без окремого підтвердження власника.

Якщо автор Git ще не налаштований, виконайте **локально в цій папці**, не надсилаючи дані чи токени в чат:

```powershell
git config user.name "Ваше ім'я"
git config user.email "Ваш email або GitHub noreply"
node scripts/check-source-handoff.mjs --staged
git diff --cached --stat
git commit -m "Initial source handoff for independent technical evaluation"
```

Локальний `origin` налаштований без мережевого запиту. Remote призначений для `https://github.com/leusyan16-ux/asia-edition.git`. Авторизацію GitHub налаштовуйте штатно через GitHub Desktop або менеджер облікових даних, не додаючи токени в URL чи файли репозиторію.

Лише після окремого підтвердження завантаження:

```powershell
git branch -M main
git push -u origin main
```

Не застосовуйте `--force` для заміни невідомої віддаленої історії. Передачу вихідного коду не слід поєднувати з deploy або застосуванням SQL-міграцій.
